# Πρόταση Schema (SQLite μέσω Drizzle)

> Draft v0.1 — πρόταση προς συζήτηση, **όχι** τελικό. Στόχος: να καλύπτει τα 4 κομμάτια
> της εφαρμογής (Υπηρεσίες Μήνα, Ημερολόγιο, Στατιστικά, Επεξεργασία) και να κρατά
> καθαρά διαχρονικά στατιστικά.

> **Σημείωση (D9):** Το schema σχεδιάστηκε αρχικά για Postgres (D8). Με τη στροφή σε
> τοπικό **SQLite** οι τύποι παρακάτω είναι «λογικοί» — η πραγματική αποτύπωση γίνεται με
> **Drizzle** και τις εξής αντιστοιχίες:
>
> | Λογικός τύπος (πίνακες κάτω) | SQLite / Drizzle |
> |---|---|
> | `uuid PK` | `text` PK (π.χ. `crypto.randomUUID()` στον κώδικα) |
> | `text`, `int`, `bool` | `text`, `integer`, `integer` (0/1) |
> | `date` | `text` ISO `YYYY-MM-DD` |
> | `timestamptz` | `text` ISO 8601 (ή `integer` epoch) |
> | `jsonb` (π.χ. `schedules.settings`) | `text` με JSON (Drizzle `mode: 'json'`) |
>
> Τα ξένα κλειδιά (FK) υποστηρίζονται από το SQLite (με `PRAGMA foreign_keys = ON`).
> Το **RLS δεν χρειάζεται** τοπικά (single-machine).

## Βασική ιδέα

Όλα στηρίζονται σε **έναν πίνακα γεγονότων**: το `assignments`. Κάθε γραμμή =
«το άτομο Χ έκανε την υπηρεσία Υ τη μέρα Ζ (στη μονάδα Μ)». Από αυτόν τον πίνακα
παράγονται **όλα** τα στατιστικά με SQL — δεν κρατάμε διπλά αθροίσματα.

```
ranks ──< people ──< assignments >── duty_types
                          │   │
                          │   └──> units        (δική μας / εξωτερική μονάδα)
                          └──> schedules         (στιγμιότυπο μήνα)
people ──< unavailabilities                      (δηλώσεις «να μην κάνω»)
calendar_days  (τύπος ημέρας ανά ημερομηνία: καθημερινή/ΣΚ/αργία/ειδική)
```

## Πίνακες

### `ranks` — Βαθμοί
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| name | text | π.χ. «Στρατιώτης», «Δεκανέας» |
| sort_order | int | ιεραρχική σειρά (για ομαδοποίηση/ταξινόμηση) |
| created_at | timestamptz | |

### `people` — Προσωπικό
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| full_name | text | |
| rank_id | uuid FK → ranks | |
| status | text | `active` / `frozen` (πάγωμα) / `archived` (αποχώρησε) |
| service_start_date | date | **από πότε ξεκίνησε** να κάνει υπηρεσίες (για δίκαια στατιστικά) |
| notes | text | προαιρετικά |
| created_at | timestamptz | |

> Το «πάγωμα» = `status = 'frozen'`: μένει στη βάση & στα ιστορικά, αλλά εξαιρείται
> από τη νέα κατανομή.

### `duty_types` — Είδη υπηρεσιών
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| name | text | π.χ. «Σκοπιά», «Θαλαμοφύλακας» |
| default_per_day | int | πόσες θέσεις/μέρα κανονικά |
| color | text | για το UI (badge/χρώμα στο κουτί) |
| active | bool | ενεργό για νέους μήνες |
| created_at | timestamptz | |

### `duty_type_ranks` — Ποιοι βαθμοί κάνουν κάθε υπηρεσία
(σύνδεση many-to-many: «η κάθε υπηρεσία ανάλογα με τον βαθμό»)
| στήλη | τύπος |
|-------|-------|
| duty_type_id | uuid FK → duty_types |
| rank_id | uuid FK → ranks |
| PK (duty_type_id, rank_id) | |

### `units` — Μονάδες
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| name | text | |
| is_home | bool | `true` = η δική μας μονάδα, `false` = εξωτερική |
| created_at | timestamptz | |

> Αυτό λύνει το θέμα «υπηρεσίες σε άλλες μονάδες»: κάθε `assignment` ξέρει σε ποια
> μονάδα έγινε, οπότε τα συνολικά στατιστικά τις περιλαμβάνουν αυτόματα.
> (Δες [DECISIONS.md](DECISIONS.md) για το πώς θα φαίνεται στο UI.)

### `calendar_days` — Τύπος ημέρας
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| date | date PK | |
| day_type | text | `weekday` / `weekend` / `holiday` / `special` |
| label | text | π.χ. «Δεκαπενταύγουστος» |

> Καθημερινές/ΣΚ υπολογίζονται αυτόματα· αργίες & ειδικές μέρες καταχωρούνται εδώ ως
> override. Έτσι τα στατιστικά «ανά τύπο ημέρας» βγαίνουν με ένα JOIN.

### `schedules` — Στιγμιότυπα μήνα
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| year | int | |
| month | int | 1–12 |
| status | text | `draft` / `finalized` |
| settings | jsonb | ενεργοί τύποι υπηρεσιών & πλήθος/μέρα για τον συγκεκριμένο μήνα |
| created_at / updated_at | timestamptz | |

> Κάθε μήνας = ένα `schedule`. Έτσι το «Ημερολόγιο Υπηρεσιών» ανοίγει/επεξεργάζεται
> παλιούς μήνες χωρίς να χαλάει τα υπόλοιπα.

### `assignments` — Εκχωρήσεις (ο κεντρικός πίνακας)
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| schedule_id | uuid FK → schedules | σε ποιον μήνα ανήκει |
| person_id | uuid FK → people | |
| duty_type_id | uuid FK → duty_types | |
| unit_id | uuid FK → units | δική μας ή εξωτερική |
| date | date FK → calendar_days | |
| source | text | `auto` (αλγόριθμος) / `manual` (χειροκίνητα) |
| created_at | timestamptz | |

> **Δεν** υπάρχει unique περιορισμός (person, date) → επιτρέπει, αν χρειαστεί,
> πολλαπλές υπηρεσίες το ίδιο άτομο/μέρα (π.χ. εξωτερική μονάδα). Δες DECISIONS.

### `unavailabilities` — Δηλώσεις «να μην κάνω»
| στήλη | τύπος | σημείωση |
|-------|-------|----------|
| id | uuid PK | |
| schedule_id | uuid FK → schedules | |
| person_id | uuid FK → people | |
| date | date | |
| reason | text | προαιρετικά (άδεια / προτίμηση / κ.λπ.) |

> Τα «απορριπτόμενα» κουτιά του πίνακα. Ο αλγόριθμος τα σέβεται ως hard constraints.

## Στατιστικά (παράγονται με SQL views)

Παραδείγματα views που θα κατασκευαστούν αργότερα:
- `v_person_totals` — σύνολα ανά άτομο & ανά τύπο ημέρας.
- `v_rank_averages` — ΜΟ ανά βαθμό.
- Όλα φιλτράρονται σε run-time ανά: χρονικό διάστημα, τύπο υπηρεσίας, `service_start_date`.

Ο κανόνας «δικαιοσύνης» (βλ. [DECISIONS.md](DECISIONS.md) D5) ισορροπεί ταυτόχρονα:
- **σύνολο υπηρεσιών** ανά άτομο, και
- **«βαριές μέρες»** = `day_type IN ('weekend','holiday','special')` ως ένα μέτρο.

Διαχρονικά (όχι ανά μήνα) και **κανονικοποιημένα** στον χρόνο υπηρεσίας: το
`service_start_date` είναι κρίσιμο — ΜΟ = υπηρεσίες / (διαθέσιμες μέρες από την έναρξη).

## Ασφάλεια

- **Τοπική βάση (SQLite):** το RLS του Postgres δεν εφαρμόζεται — single-machine, ένας χρήστης.
- Πρόσβαση στη βάση **μόνο server-side** (server actions / route handlers / RSC) μέσω Drizzle —
  ποτέ από τον browser.
- Κανένα πραγματικό όνομα στο repo — μόνο στο τοπικό αρχείο `*.db`, που είναι στο `.gitignore`.
  (Τοπικά επιτρέπονται πραγματικά ονόματα — βλ. [DECISIONS.md](DECISIONS.md) D9.)
